# Battle Screen - Move-to-Attack Feature Plan

## Goal
Enable player to click an enemy stack to "move to attack" when the enemy is outside direct attack range but within `battleMoveRange + range`. The unit moves to the closest valid attack position and attacks in the same turn.

## Design Decisions (Confirmed)

| Aspect | Decision |
|--------|----------|
| Trigger | Click enemy stack (not empty cell) |
| When | Enemy within `battleMoveRange + range` but outside `range` |
| Execution | Same turn: move → attack (both must succeed) |
| AP Cost | (moveSteps × tier) + attack AP (tier) |
| Pathfinding | Nearest unoccupied cell from which enemy is in `attackRange`, clear straight-line path |
| Tie-breaking | Closest to attacker (minimize move cost) |
| No valid cell | Cancel, show feedback (console log for now) |
| Visual | Green = movement range (`battleMoveRange`), Red pulsing = direct attack, Orange enemy highlight = move-to-attack available |
| Source of `moveRange` | `shipType.battleMoveRange` (not `speed`) |
| AI | Uses same `battleMoveRange` via `stack.moveRange` |
| `speed` | Unchanged for strategic map |

2. Manual: Player fleet (fighter, battleMoveRange=10, range=2) vs enemy 12 cells away
   - Select fighter → green cells show 10-cell radius
   - Click enemy → moves 10 cells, attacks from 2 cells away
   - AP consumed: 10×1 (move) + 1 (attack) = 11 AP (but only 10 available!) → should fail
   - Wait, fighter tier=1, so 10 move + 1 attack = 11 > 10 AP → needs 2 turns or larger AP pool
   - This is a balance concern — verify AP model works

## AP Balance Note

With `battleMoveRange` values (scout=12, fighter=10, dreadnought=2) and tier-based AP:
- Fighter: moveRange=10, tier=1 → max move cost 10 AP, leaving 0 for attack
- Scout: moveRange=12, tier=1 → can't move full range AND attack in same turn
- This may be intentional (forces multi-turn approach) or may need AP_PER_TURN increase

**Decision:** Keep as-is for now. If balance is off, it's a data tuning issue, not code.
